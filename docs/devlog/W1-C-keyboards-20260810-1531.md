## 未修正、寫進 devlog 交給 lead / :ime 裁決

**finding：`symbol_standard.json` 控制列 `language_toggle`/`symbol_toggle` 掛法語意不對稱。**

檢查了 `:common` 的 `KeyAction.kt` KDoc 字面語意：

- `symbol_toggle` = 「切換到符號鍵盤（vs 注音/字母鍵盤）」
- `language_toggle` = 「切換到英文/數字鍵盤」

`zhuyin_4x10_{portrait,landscape}.json` 控制列的「符號」→`symbol_toggle`、「英數」→`language_toggle`
跟字面語意一致（在 zhuyin 鍵盤上，這兩顆鍵字面意義上就是「去符號」「去英數」，沒問題）。

`symbol_standard.json` 控制列目前是「注音」→`language_toggle`、「ABC」→`symbol_toggle`，兩個都跟
字面語意方向相反：

- 「ABC」在字面語意下應該是 `language_toggle`（去英數）——這部分**可以**改成自洽。
- 但「注音」按下去的意圖是「回到注音鍵盤」，而 `KeyAction` 目前**沒有任何一個 action 字面上代表
  「切換到注音鍵盤」**——`symbol_toggle`／`language_toggle` 只覆蓋「去符號」「去英數」兩個方向，
  沒有「去注音」。所以「注音」這顆鍵在嚴格單向語意下**無法自洽**，不管掛哪個 action 都是字面錯的。

**嘗試過的修法與為何撤回**：曾把「ABC」單獨改成 `language_toggle`（唯一能自洽的那一半），但這樣會
讓「注音」（維持 `language_toggle`，因為它沒有正確答案）跟「ABC」兩顆功能完全不同的鍵掛同一個
action——兩顆鍵按下去（在目前 `:keyboards` 只回傳資料模型、`:ime` 還沒接上實際行為的情況下）語意
上會被判成同一件事，這是比原本「方向相反但至少兩顆鍵動作不同」更嚴重的新問題。因此撤回這個部分修正，
`symbol_standard.json` 維持原狀（`git diff` 對此檔案為空）。

**判斷**：字面語意本身無法支撐 `symbol_standard.json` 需要的「回到注音」這個按鍵，除非
`symbol_toggle`／`language_toggle` 被定義成**雙向 toggle**（例如 `language_toggle` 其實是「zhuyin
⟷ 英數」雙向切換，跟目前所在鍵盤無關；`symbol_toggle` 是「symbol page ⟷ 進入前的主鍵盤」雙向切換）
——若真是雙向 toggle，現有的四顆鍵指派其實是自洽的，只是 KDoc 字面用「切換到 X」這種單向措辭容易
誤讀。**這個「單向跳轉 vs 雙向 toggle」的實際語意，是 `:common` 契約層級的決定，:keyboards 這個
子代理無法單方面判定，也依規則不能動 `:common`**，故交給 lead／`:ime` 裁決：

- 若定案為雙向 toggle：`symbol_standard.json` 現況不用改，只需要把 `KeyAction.kt` 的 KDoc 措辭
  改成明確的雙向描述（消歧義），避免下一個人再誤讀成單向。
- 若定案為單向跳轉：`KeyAction` 需要新增一個「切換到注音鍵盤」的 action 變體（例如
  `zhuyin_toggle`），`symbol_standard.json` 的「注音」鍵改用新變體，「ABC」鍵改用 `language_toggle`。
